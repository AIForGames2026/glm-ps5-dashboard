How expert swapping works

GLM-5.3-Flash is a 321B-parameter mixture-of-experts model (18B active per token). It does not fit in a PS5's 16 GB of memory, so the engine keeps the always-needed weights resident and streams the experts it needs from the SSD, keeping the popular ones in a memory pool.

The model, in numbers

  • 45 layers; each layer has 288 routed experts (plus 1 shared) and the router picks 8 of them for every token.
  • Per token that is 45 × 8 = 360 expert lookups. Each lookup is either a hit (expert already in memory) or a miss (read it from the SSD, evict the least recently used one).
  • Only a fraction of each layer's experts fit in the pool; the dashboard's Monitor tab shows the real pool size and live hit rate. The slider below is a default of 126 of 288 for illustration.
  • Speed is bound by SSD reads, so fewer misses per token = faster decoding.

The trade-off is real: a bigger bias means fewer SSD reads but more tokens routed to a different expert than the model would have chosen. The engine's served bias was chosen by measuring output quality against exact routing (see docs/CACHE-AWARE-ROUTING.md and docs/GLM53-ROUTING-POLICY.md in the repository).

How this differs from Strata

Strata is the open-source engine we benchmarked against and borrowed the dashboard design from. It runs the same class of model on desktop-class machines.
